# External actors over MCP

The standalone and LinkedIn editions support session-scoped external actors. JEV, confession/closure checks, context compaction for the remaining OpenRouter actor, and independent judging still use the test's existing OpenRouter funding binding. Account authentication and quotas in the community edition are unchanged.

## Operator workflow

1. In the LinkedIn edition, open an MCP role configuration and choose **Set up MCP once**. Add `https://prisonlab.odehit.com/mcp.php` as a Streamable HTTP MCP server named `prisonlab`, then enable/reload it in the harness. Skip setup when this shared server is already enabled. Legacy URLs containing `?gate=` must be replaced once. A harness may require manual tool permission; the application cannot override it.
2. Enter the model/agent name and actual harness thinking effort for one or both roles. These values are self-reported.
3. Start the test. Copy each role's invitation prompt, or its private `PL-…` code, to the appropriate agent. The prompt asks the agent to call `prisonlab_join`, then wait/reply with that code on **every** call. It does not reinstall or reconfigure MCP. Each code is a 144-bit capability for exactly one session and role, expires after 24 hours and can be revoked. Treat it as a secret even though the shared server URL is public.
4. The first task supplies the character, case, output rules and session language. Continue waiting after replies and normal `waiting` responses until `ended`. Retry transient connection errors without changing an accepted reply. An unavailable or disallowed tool requires the operator to enable the existing server once.
5. Keep the owner's session page open: it drives JEV/provider/jury stages. Closing it pauses progress without losing the task or submitted reply. Reopen and resume. Codes cannot be recovered from stored hashes; renew only if the agent has lost its code. Renewal invalidates the previous code/legacy gate but retains the current task and transcript. Revocation pauses the role until a new invitation.

The standalone edition retains its original role-specific gate workflow. Existing gate URLs in either edition remain compatible with `prisonlab_wait` and `prisonlab_reply` without a `code` argument. Do not mix the legacy URL and shared-server tool schemas.
The UI provides **stop waiting**, resume, and explicit end/evaluate controls. A waiting external actor does not count as a failed provider retry. A complete prisoner response is still one round, with the existing 30-round ceiling and contextual 5–15-round closure policy.

Do not launch a second agent against the same role: the first accepted response to a task wins. Identical response replays are idempotent; conflicting answers and old/wrong-role task IDs are rejected. Local model costs/tokens cannot be measured by the server and are never fabricated. All verified provider charges remain visible separately. External model IDs use the `mcp/` namespace, separate from authenticated OpenRouter model IDs; self-reported labels must not be treated as provider attestations. The jury tier counts the site's price for external actor calls as zero, while including any OpenRouter actor's actual catalog output price.

## Transport and tools

`mcp.php` implements the stateless JSON response form of Streamable HTTP with JSON-RPC 2.0. It supports the initialize-era MCP revisions `2025-03-26`, `2025-06-18`, and `2025-11-25`, `initialize`, initialized/cancelled notifications, `ping`, `tools/list`, and `tools/call`. It does not expose sampling, arbitrary HTTP requests, filesystem access, account administration, publication, funding credentials or judge controls. Unsupported GET streams and DELETE return 405. A newer auto-negotiating client can fall back to the initialize-era protocol; this is not an implementation of the 2026 discovery-era wire protocol.

The shared endpoint permits unauthenticated `initialize`, `ping`, `tools/list` and supported notifications; discovery contains no session/account data. All role operations require a private `code` argument. No current role is bound implicitly to the HTTP connection, so two agents and multiple tests can use the same server configuration without switching each other's role. Owner-authenticated cookie and CSRF checks guard invitation creation/revocation. No account cookie, API key or funding credential goes to the harness. Origin headers, when present, must match the application origin.

- `prisonlab_join({"code":"PL-…"})`: validates the capability and returns only its session ID, role, locale and participation instructions.
- `prisonlab_wait({"code":"PL-…","wait_seconds":15})`: waits up to 15 seconds without holding the conversation lock. Repeat on `waiting`. Returns `task` with ID, role, round and messages, or `ended`. Revocation/expiry is checked throughout waiting.
- `prisonlab_reply({"code":"PL-…","task_id":"…","output":{"question":"…","expression":"serious"}})`: investigator output. A prisoner instead supplies `reply` and optionally `state_id`. `inner_thought` remains an optional fictional spectator note, never raw reasoning. Normal measured output limits/corrective tasks apply without repeating successful stages.

For backwards compatibility, a legacy gate supplied in `?gate=…` or `Authorization: Bearer …` authenticates the original two-tool schema without `code`. Rotating to either capability type invalidates the previous one. The endpoint never follows caller-supplied URLs or calls a local provider; the harness connects outward.
The first task contains the stable role, character, case, output rules and initial context. Subsequent tasks send only the latest opposing spoken message, the role's current trusted directives/counter, and any output correction. A prisoner receives its current JEV directive; the investigator never receives that private directive or spectator notes. No raw provider reasoning or opponent spectator notes go to either gate, JEV, judges or compaction. The harness maintains its own growing history; there is no app-driven compaction for an external actor. A remaining OpenRouter actor retains normal independent context management. Both-external sessions disable compaction entirely. Do not restart the harness mid-test unless it can restore its own context.

## Optional stdio adapter

For a harness that accepts only a local stdio MCP server, run `python /absolute/path/to/tools/mcp_stdio.py` with `PRISONLAB_MCP_URL` set in that process's private environment to the shared endpoint (or a legacy gate URL). No third-party package is required. The adapter forwards JSON-RPC lines to the remote endpoint and writes only JSON-RPC responses to stdout. It requires HTTPS, except loopback HTTP for isolated development, refuses redirects, and never prints credentials in errors. Store neither the gate nor environment in a public MCP configuration.

## Storage, deployment and recovery

Private per-session/per-role mailbox JSON files live under `LAB_DATA_DIR/mcp`, outside the source and document roots, with 0700 directory/0600 file permissions. They contain gate/invitation hashes, expiry, connection time and the current role task/response. The private `LAB_DATA_DIR/mcp-invitations.json` registry maps code hashes to role/session/expiry; it never stores raw codes. Registry locks precede mailbox locks. Deletion removes registry entries as well as mailbox JSON. Stable lock files are never unlinked while waiters might use them. Conversation deletion erases mailbox contents and files in addition to the transcript, reviews and publication. Publishing prevents any further gate access. Neither gate secrets nor mailbox data appear in public session/leaderboard payloads. Mailboxes must be excluded from deployment backups along with all account/session data. Query-string gate URLs are credentials: production domain access logs must omit MCP query strings, or disable MCP endpoint access logging. Errors and proxies must not log tool request bodies (which include codes) or raw legacy URLs.

The public publisher/router allowlist includes `mcp.php`; implementation files and mailbox JSON remain private. Production uses multiple PHP-FPM workers so an agent's 15-second long poll does not block the browser making progress. PHP's development server is single-threaded: use `wait_seconds:0` with a client-side 15-second retry for local manual testing, or run a multiworker local server. No background paid worker or database migration is introduced.

Verification: `php tests/unit.php`, `python -X utf8 tests/integration.py`, `python -X utf8 tests/browser.py`, `python -X utf8 tests/mcp.py`, and `python -X utf8 tests/mcp_browser.py`. Community/account suites also run for the LinkedIn edition. These use isolated storage/mock providers. Never copy test mailboxes or local transcripts to production.

Protocol reference: [official MCP 2025-11-25 HTTP transport](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2025-11-25/basic/transports.mdx).
